## Meta-lessons for whoever continues

1. **The render pipeline was where all the bugs were** — hacking around it
   (hardcoded images, manual manifests) would have proven nothing. Testing
   through the real installer/MCO/CNO path surfaced 14 distinct product bugs.
2. **In-subnet VIPs mask BGP failures** (kube-vip also puts the address on the
   interface → L2 ARP serves it). Several runs "half-worked" because of this.
   For strict L3 validation, move the VIPs off-subnet (future work).
3. **`make redeploy` is a trap** (run2). The redeploy recipe is in RUNBOOK.md.
4. The exact-image standalone lab (lab/) cracked in 30 minutes what
   cluster-level probing couldn't in hours — build the small repro early.
5. **Overlay BOTH zebra paths.** The metallb-frr image ships zebra at
   `/usr/lib/frr/zebra` AND `/usr/libexec/frr/zebra`; overlaying only one
   silently runs the unpatched binary (cost a false "fix doesn't work" lab
   result before run18).
6. **Live-validate review-suggested hardening before pushing it.** Of the
   MCO PR #6326 review round, two suggestions would have silently broken the
   VIP path (`drop: ALL` on the frr container; probes that restart-flap all
   BGP sessions on a node) and one was based on a wrong premise (emptyDir
   UID-writability — kubelet creates them 0777). Hot-editing the static pod
   manifest on one master and watching the ToR is a five-minute test that
   settles any of these definitively.
